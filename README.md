# small-transformers-go

A CPU transformer implemented in Go: download text, train from scratch, fine-tune conversational replies, evaluate checkpoints, and chat locally without Python or PyTorch. macOS+cgo uses Apple Accelerate BLAS/vector routines; `CGO_ENABLED=0` uses pure-Go kernels. Requires Go 1.27 and, for macOS cgo, Xcode Command Line Tools.

The target is a small Shakespeare-style conversational companion. It is not a general-knowledge assistant or the real Shakespeare. Conversational quality is still being validated; a low teacher-forced loss alone does not establish that it answers freely phrased questions correctly.

## Chat

```bash
GOMAXPROCS=2 VECLIB_MAXIMUM_THREADS=1 go run . chat \
  -model checkpoints/shakespeare-chat.bin
```

Type a short English message, then Enter. `/quit` exits. Messages are currently answered independently: there is no reliable conversational memory. The character vocabulary supports printable ASCII; unsupported characters produce an error rather than silently changing the message.

One reply without an interactive session:

```bash
GOMAXPROCS=2 VECLIB_MAXIMUM_THREADS=1 go run . chat \
  -model checkpoints/shakespeare-chat.bin \
  -prompt "I feel lonely. What wouldst thou advise?" -temp 0.7
```

Replies are generated by the model, not selected by a keyword lookup. Generation stops at a learned end-of-reply marker or the character limit (`-n 200` by default). The limit includes any generated stop-marker characters. A completion-only checkpoint is rejected by `chat`.

## Train the language-model foundation

```bash
go run . download
go run . train -out checkpoints/new-base.bin \
  -steps 5000 -batch 8 -seq 256 -dim 192 -heads 6 -layers 6 \
  -lr 0.0008 -eval-every 200
```

The first 90% of Shakespeare characters train the foundation; the final 10% are validation only. Vocabulary metadata uses the whole corpus. `-split 1` disables validation and saves the final weights; it is intended for smoke tests or deliberate overfitting. With validation enabled, the output is atomically replaced only when validation improves. It is the best checkpoint, not necessarily the last.

## Conversational fine-tuning

```bash
go run ./cmd/chat-data
go build -o small-transformers-go .

nice -n 10 env GOMAXPROCS=2 VECLIB_MAXIMUM_THREADS=1 GOMEMLIMIT=384MiB \
  ./small-transformers-go train -chat \
  -data data/shakespeare-chat-train.jsonl \
  -validation data/shakespeare-chat-validation.jsonl \
  -init checkpoints/shakespeare-parallel.bin \
  -out checkpoints/new-chat.bin \
  -steps 6000 -batch 2 -lr 0.00015 -chat-focus 32 -eval-every 200
```

The supplied seed files are original, synthetic Shakespeare-style prose, not quotations. They cover 39 limited themes, including greetings, identity, feelings, learning, work and nature. The generator creates 27,108 training examples, 351 validation examples and 117 test examples (39 distinct test questions, each with three acceptable reference replies). Framing and case variants expand training questions. Validation and test questions are excluded from training; reference answers can recur across the splits. This tests paraphrase/intent handling within a narrow domain, not novel knowledge or broad reasoning.

Question/answer JSONL format:

```json
{"question":"Hello.","answer":"Good morrow, gentle friend!"}
```

Fine-tuning masks questions and padding: only reply characters and the end marker contribute to the full-reply loss. Random left-padding during training discourages memorizing absolute reply positions. With `-chat-focus 32`, half the minibatches supervise only the first 32 reply characters and half supervise full replies. Validation/checkpoint selection then scores the first 32 characters. This gives question-conditioned reply beginnings more influence than easy memorized continuations. `-chat-focus 0` uses full replies throughout.

`-init` loads weights, architecture and vocabulary; it does not restore Adam state or the learning-rate schedule. Chat training expands the vocabulary while preserving existing embedding/output weights. If validation never improves, the initial checkpoint is retained. Use a different output path to preserve the source checkpoint.

## Evaluate

Foundation, fixed validation windows:

```bash
go run . eval -model checkpoints/shakespeare-parallel.bin -batch 2 -batches 32
```

Add `-batches 0` to score the complete held-out tail, including its partial final window. Supply the same original corpus and split used for training. The tail is genuinely held out only when excluded during training; older full-corpus smoke models do not establish generalization.

Chat, complete validation set:

```bash
go run . eval -chat -model checkpoints/shakespeare-chat.bin \
  -data data/shakespeare-chat-validation.jsonl -batch 2 -batches 0 -chat-focus 32
```

Use `-chat-focus 0` for full-reply loss. Full-reply, reply-prefix and foundation losses are different measurements and should not be compared as if interchangeable. All use natural-log next-character cross-entropy and character perplexity. Inspect actual generated replies on excluded questions too: teacher forcing can hide a model ignoring the question.

## Text completion

```bash
go run . generate -model checkpoints/shakespeare-parallel.bin \
  -prompt "ROMEO:" -n 500 -temp 0.8 -topk 20 -seed 7
```

This continues a text prefix; it is not conversational answering. Output contains the prompt plus exactly `n` new characters. Fixed seeds reproduce samples on the same backend. `-topk 1` is greedy; `-topk 0` disables filtering. There is no KV cache.

## Resource controls and tests

`nice -n 10` gives foreground work scheduling preference. `GOMAXPROCS=2`, `VECLIB_MAXIMUM_THREADS=1` and batch size 2 reduce training load. `GOMEMLIMIT=384MiB` is a soft Go-memory limit, not a hard resident-RAM cap. The measured capped foundation refinement used about 1.18 CPU cores on average and peaked at 250 MiB resident memory. Further chat-training measurements are saved under `runs/`.

Only Ginkgo end-to-end tests, exercising actual binaries and an offline HTTP fixture:

```bash
GOMAXPROCS=2 VECLIB_MAXIMUM_THREADS=1 go test ./... -count=1 -v
CGO_ENABLED=0 GOMAXPROCS=2 go test ./... -count=1 -v
```

Scenarios include the full foundation pipeline, disjoint validation, checkpoint selection, vocabulary-expanded chat fine-tuning, unseen-length replies, end-of-reply stopping, piped interactive messages and rejection of leaked questions. See [PLAN.md](PLAN.md) for progress and measured evidence.
